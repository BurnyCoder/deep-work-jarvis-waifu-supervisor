Build a Windows productivity enforcement app that helps users maintain deep focus during work sessions through a combination of blocking, monitoring, and AI-powered feedback.

  1. Website Blocking
    - Block distracting websites (Reddit, YouTube, Twitter/X, Discord, Hacker News,
   LinkedIn, Bluesky, Substack, Facebook, LessWrong, EA forum, 4Chan)
  2. App Killing
    - Continuously kill distraction apps (Discord, Telegram, Steam)
  3. AI-Powered Productivity Monitoring each 5 minutes
    - Capture screenshots from all monitors
    - Capture webcam image using OpenCV
    - Stitch all captures into a single labeled image
    - Accumulate N captures (default: 5) before sending to vision LLM for analysis using OpenAI API GPT 
    - Return JSON response with productive: yes/no and encouraging/gentle reason
  4. Text-to-Speech Feedback
    - User enters a topic (or selects previous topics from drop down menu) to work on and say "good luck on x topic" each time generated by LLM
    - Speak gentle nudges when not productive generated by LLM according to the captures
    - If productive for 30 minutes, say good job generated by LLM according to the captures
  5. Operating Modes and Options
    - ON: Blocking enabled + monitoring active
    - OFF: Everything disabled
    - BREAK: Timed break with auto-restore (unblock sites temporarily) 
    - - Option to allow only some site or app while continuing to block everything else
    - - User must say what's the break for and for how long, and TTS responds
    - - Break on social media mode vs break outside of computer mode
    - Option that tracks social media allowance, cap it at 2 hours per day, do not allow breaks there
    - Option that has productive project that needs some social media that allows it, specify which one
  6. Confirmation Phrase Security
    - Require typing a phrase like "I will not stop cool deepwork session" to disable. Prevents impulsive disabling when distracted.
  7. Web UI
  8. Result Storage
    - Save to results folder

Core behaviors

- Modes: ON = hosts block applied + killer + monitor threads active. OFF = everything cleared (requires exact phrase I will not stop cool deepwork session, else HTTP 403). BREAK = user gives purpose + minutes + type (social_media | away) + optional allowed sites/apps; TTS acknowledges; enforcer thread auto-restores at expiry. away breaks
pause monitoring. Social breaks draw down a persisted per-day allowanrejected once exhausted. A configured "project" can allowlist specificsocial sites while ON.
- Monitoring loop (300s): capture all monitors + webcam → stitch labeled JPEG → save to results/captures/ → after 5 captures, one vision call returns {productive: bool,
reason: str}; unproductive → LLM-written gentle nudge spoken; 30 consLLM praise spoken (once per streak). Full prompts/responses logged uncutto logs/ and saved as JSON in results/llm/.
- Hosts safety: idempotent fenced block, clear() on OFF and atexit; README documents manual removal, browser Secure-DNS (DoH) bypass caveat (must be off for hosts blocking
to work), and the Defender HostsFileHijack flag.
